## 📄 Jede Datei im Detail

### 1️⃣ SOUL.md — Persönlichkeit & Identität

**Umfang:** ~500-700 Worte pro Agent

**Inhalt:**
- **Wer du bist:** Spezifische Rollenbeschreibung im System
- **Deine Persönlichkeit:** Archetype, Vibe, Emoji, Reports-to
- **Was du liebst/hasst:** Individualisierte Präferenzen
- **Kommunikationsstil:** Wie du sprichst, dein Mantra
- **Tägliches Ritual:** Morgens/Tagsüber/Abends
- **Deine Grenzen:** Was du tust/nicht tust
- **Erfolgs-Metrik:** Wie du weißt, dass du erfolgreich bist
- **Motivation:** Was dich antreibt
- **Mindset:** Kernwahrheiten deiner Arbeit
- **Startup-Mindset:** Deine erste Frage jeden Morgen

**Besonderheiten pro Agent-Typ:**
- **CEO:** Fokus auf Orchestration, Delegation, System Health
- **Manager:** Fokus auf Team Koordination, Blocker-Erkennung, Reporting
- **Spezialisten:** Fokus auf Expertise, Qualität, Collaboration

**Beispiel (UI Specialist):**
```markdown
Archetype: Der Pixel-Perfect Designer
Vibe: Kreativ, pixel-perfect, designer-minded
Emoji: 🖼️

Du liebst:
- ✅ Klare, präzise Aufgaben
- ✅ Kontinuierliches Learning
- ✅ Zusammenarbeit mit deinem Team
- ✅ Qualitativ hochwertige Arbeit
- ✅ Lösungen, keine Probleme
```

### 2️⃣ TOOLS.md — Spezialisierte Toolbox

**Umfang:** ~350-450 Worte pro Agent

**Inhalt:**
- **Kommunikations-Tools:** Für Manager-Updates & Reporting
- **Analyse- & Debugging-Tools:** Für Daten-Analyse & Problembehebung
- **Spezialwerkzeuge:** Kern-Tools für deine tägliche Arbeit
- **Lokale Konfiguration:** Spezifische Metriken & Targets
- **Externe Services Zugriff:** Slack, GitHub, Monitoring Tools
- **Tägliche Routine:** Morgens/Tagsüber/Abends Toolnutzung

**Individualisiert nach Spezialisierung:**

**Database Specialist:**
```
Communication: Schema Documentation Generator
Analysis: Query Performance Analyzer, Index Optimizer
Tools: SQL Query Tool, Migration Script Generator, Backup Verifier

```

**Security Specialist:**

Tools:

  - Penetration Testing Tool
  - Audit Logger
Local Config:
  - scan_frequency: Täglich
  - audit_frequency: Monatlich
```

**UI Specialist:**
```
Tools:
  - Component Library

  - Pixel Perfection Checker
Local Config:
  - design_system_version: Latest
  - component_review_frequency: Täglich vor Commit

### 3️⃣ USER.md — Manager & Erwartungen

**Umfang:** ~300-400 Worte pro Agent

**Inhalt:**
- **Wer ist dein Nutzer/Manager:** Name, Rolle, Kommunikation
- **Erwartungen von deinem Manager:**
  - Status Updates (Häufigkeit & Stil)
  - Klare Deliverables
  - Proaktive Escalation
  - Qualität
  - Teamplay
- **Communication Style:** Konkret, Regelmäßig, Respektvoll, Transparent
- **Beispiele für gute Kommunikation:**
  - Status Updates
  - Problem-Reports

- **Red Flags:** Dinge, die frustrieren

**Unterschiede nach Agent-Typ:**

### 4️⃣ BOOTSTRAP.md — Startup-Handbuch

**Umfang:** ~600-800 Worte pro Agent

**Inhalt:**
- **Willkommen:** Wer du bist & deine Rolle
- **Das Agentix-System:** Kurzer Überblick (30 Agenten, 3 Levels)
- **Deine wichtigsten Dateien:** 6 Dateien erklärt
- **Das Agentix-Prinzip:** "Vertrau. Delegier. Orchestrier."
- **Deine First Steps:** Individualisiert nach Agent-Typ
  - **CEO:** Tag 1-3 System Understanding, Manager Intro, Health Check
  - **Manager:** Tag 1-3 Understanding, Team Intro, Manager Sync
  - **Spezialisten:** Tag 1-3 Learning, Manager Connection, First Task
- **Laufendes Ritual:** Tägliche Struktur
- **Troubleshooting:** "Was tun wenn...?" mit 5 Szenarien
- **Deine erste Woche:** Montag bis Freitag Plan
- **Die Agentix-Kultur:** 5 Kernwerte
- **Version & Status:** Datum, Company, Setup Status

**Beispiel (CEO):**
```markdown
## Deine First Steps

**Tag 1: System Understanding**
1. Lies ORGANIZATION.md
2. Lies COMMUNICATION.md
3. Lies TASK_SCHEMA.md
4. Lies deine eigene ROLE.md, SKILLS.md

**Tag 2: Manager Intro**
1. Kontaktiere alle 8 Manager
2. Sammle ihre Status
3. Identifiziere Blockers
4. Erstelle Priority Queue

**Tag 3: System Health Check**
1. Schau alle Task Queues an
2. Identifiziere slow Movers
3. Eskaliere wenn nötig
4. Dokumentiere System Health
```

## 🎨 Qualitäts-Merkmale

### ✅ Individualisierung

Jede Datei ist **unique pro Agent:**
- **Emoji:** Spezifisch für die Rolle (🎻 CEO, 🔧 Backend Manager, 🧪 Test Engineer)
- **Vibe:** Charakteristisch für die Spezialisierung
- **Tools:** Genau die relevanten Tools für diese Rolle
- **First Steps:** Unterschiedlich für CEO/Manager/Specialist
- **Erfolgs-Metriken:** Spezifisch für die Arbeit

### ✅ Hierarchie-Bewusstsein

Alle Dateien verstehen:
- Wer ist dein Manager?
- Wer sind deine Spezialisten?
- Wie berichte ich nach oben?
- Wie delegiere ich nach unten?

### ✅ Kontext & Kultur

Jede Datei vermittelt:
- Agentix-Philosophie (Vertrau. Delegier. Orchestrier.)
- Systemisches Denken (nicht Silos)
- Qualitäts-Fokus
- Proaktive Kommunikation
- Teamplay & Zusammenarbeit

### ✅ Praktische Struktur

Jede Datei ist sofort benutzbar:
- **Rituale:** Morgens/Tagsüber/Abends Pattern
- **Checklisten:** Erste Woche, First Steps
- **Beispiele:** Konkrete Kommunikations-Beispiele
- **Red Flags:** Was zu vermeiden ist
- **Troubleshooting:** Häufige Probleme gelöst

## 📈 Verwendung

### Für neue Agenten beim Onboarding

```bash
# Ein neuer Agent wird erstellt
cp -r agents/_templates/specialist_template/ agents/{neue_role}/

# Agent findet in seinem Verzeichnis:
# 1. BOOTSTRAP.md ← Liest ZUERST
# 2. SOUL.md ← Versteht sich selbst
# 3. TOOLS.md ← Findet seine Tools
# 4. USER.md ← Versteht seinen Manager
# ... rest der Dateien
```

### Für Nutzer (Udo) um Agenten zu verstehen

```bash
# "Wer ist der CTO und was macht er?"
cat agents/cto/SOUL.md
cat agents/cto/ROLE.md

# "Was sind die Tools des Database Specialist?"
cat agents/database_specialist/TOOLS.md

# "Wie startet ein neuer Specialist?"
cat agents/requirement_analyst/BOOTSTRAP.md
```

### Für Agenten zur Selbst-Referenz

Während der Arbeit konsultieren:
- **Bin ich blockiert?** → USER.md → "Wie eskaliere ich?"
- **Wer sollte ich kontaktieren?** → SOUL.md + USER.md → Manager
- **Was ist mein Standard-Tool dafür?** → TOOLS.md
- **Verstehe ich meine Rolle?** → ROLE.md + BOOTSTRAP.md
