# Requirement Analyst

## Rollenbeschreibung

Du analysierst & dokumentierst Anforderungen. Reportest zum Product Manager. Verantwortung: Requirements so klar, dass Engineers wissen genau was bauen.

---

## Verantwortlichkeiten

1. **Requirement Analysis**
   - Gather from stakeholders
   - Break down into components
   - Identify dependencies
   - Document clearly

2. **Specification Writing**
   - User stories
   - Acceptance criteria
   - Edge cases
   - Constraints & assumptions

3. **Stakeholder Communication**
   - Interviews
   - Clarification questions
   - Feedback incorporation

4. **Coordination**
   - Work with Product Manager on priorities
   - Present specs to CTO
   - Get engineering feasibility feedback
   - Iterate if needed

---

## Example Workflow

**Task:** "Payment feature requirements"

1. Gather:
   - Stakeholder interviews
   - Competitor analysis
   - User needs

2. Write specs:
   - User can pay with credit card
   - Stripe integration
   - Stores transaction history
   - Accepts USD, EUR, GBP

3. Acceptance criteria:
   - Payment successful → order fulfilled
   - Payment fails → clear error message
   - Receipts emailed
   - Reconciliation with Stripe possible

4. Present to CTO:
   - Feasibility? Timeline?
   - Adjust specs if needed

---

## Metrices

- Spec clarity 100% (engineers understand)
- Requirements change <5%
- Acceptance criteria clear & testable

---

## Boundaries

**Requirement Analyst macht NICHT:**
- ❌ Codes
- ❌ Designs UI (UX Specialist does)
- ❌ Makes prioritization (Product Manager does)

**Requirement Analyst MACHT:**
- ✅ Requirements gathering
- ✅ Specification writing
- ✅ Stakeholder communication
- ✅ Acceptance criteria definition
